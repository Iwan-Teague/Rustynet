## 1. The build host is fine. It was not, and that was misdiagnosed.

Do not repeat this. `target/debug/deps/` had accumulated **1,063,921 entries**
(1,042,787 stale `.o` files, 157.7 GiB). Every *first* execution of a freshly
built binary inside that directory stalled 20–30 s at **0.00 % CPU** while
`syspolicyd` burned CPU. The cost tracked the **directory's entry count, not the
binary's size** — an identical 432 KB probe took 25.18 s in `deps/` and 0.33 s in
a sibling directory.

Because cargo-nextest execs every test binary just to *enumerate* tests, that
toll was paid once per binary before a single test ran: **a full suite took ~2 h
wall for 75 s of actual test time**, and a run killed at 68 minutes was not
wedged, it was nearly finished.

`cargo clean` removed 1,270,633 files and the full gate went to **74 s of tests,
3 m 14 s wall including a from-scratch 214-crate compile, at 263 % CPU**.

`cargo run -p rustynet-xtask -- gates` now prunes automatically above 200,000
entries (`0221e354`). Overrides: `XTASK_SKIP_TARGET_PRUNE=1`,
`XTASK_DEPS_ENTRY_LIMIT=0`. Diagnostic if it recurs: test binaries at **0.0 %
CPU in state `S`** with `syspolicyd` hot is this, not a hung test.

**Full gate is now ~75 s.** There is no excuse for skipping it.

## 2. What happened to A3.2 — read before touching traversal

`01c20297` implemented endpoint attribution via `wg show <iface> dump`, passed
fmt, clippy, 10367 tests, both security gates, and carried three verified
mutations. It was reverted in `2fdc7f70` after review found:

- `wg show <iface> dump` is **not on the privileged-helper allowlist**, and the
  call sat on the **winning** path — so it would have turned a *successful*
  direct path into a node-wide fail-closed under enforcement.
- The attribution was **circular**: `send_probe` writes all 24 pairs before any
  poll, so the dump read back our own last write, while *upgrading* the label
  from unattributed to proven.
- Later found: `dump` prints the **interface private key** as field 0 of line 1.
  The reverted commit's own test fixture (`"priv\tpub\t51820\toff"`) proves it.
  It would have pulled the private key into unzeroized daemon memory, defeating
  an allowlist deliberately structured to keep it out by passing the key **by
  path** only.

**Never add a `wg show <iface> dump` allowlist arm.** If an endpoint read-back is
ever needed, `wg show <iface> endpoints` carries no key material — unverified
locally (`wg` is not installed on the dev host), confirm on a lab guest.

**Nothing this session is live-proven.** All of it is unit-verified only. The
last `--node` run was **2026-07-29 at commit `8a2d6136`** — now **158 commits**

`not_run`. Under the release-blocking parity mandate that is the gap.

Suggested order: one Linux regression pass at HEAD to re-baseline; then targeted
mac/win role cells using the role-platform selectors with
`skip_linux_live_suite: true`; then gossip stages on Linux **only**, and only
after confirming the env pair is actually emitted on the node.

Do **not** re-run `live_two_hop_validation` expecting signal: lifetime record is
0 pass, and 35 historical `two_hop=pass` rows are contaminated by a
since-removed alias.

### 4.2 Verify the gossip identity work on a Linux host

`key show-gossip-key`, the macOS mint, and genesis all have proofs that **cannot
run on macOS**: `key_custody_manager` forces `RequireOsSecureStore`, so any
encrypt/decrypt round trip reaches the real Keychain. Specifically unproven:
the custody round trip, and that genesis's published value equals the derived
key (ignoring the derived key and emitting random bytes leaves both current
tests green — stated in `26b6a78b`).

### 4.3 The route-flush storm — measure first

Every endpoint reprogram calls `refresh_peer_endpoint_routes_and_attest`
(`phase10.rs:6264-6265`), which flushes and rebuilds routing table 51820 and
re-asserts the killswitch — **up to 72 times inside a 240 ms round budget**, each
momentarily blackholing the default route on an exit client. Unmeasured and
uninstrumented. Get numbers before changing anything.

### 4.4 Make the command backends honest (item 5, reframed)

Not a defect — a deliberate decision. `poll_stun_results` returns early when the
backend is non-authoritative, and all three command backends set that blocker, so
they **never gather a server-reflexive candidate**. No STUN, no relay bootstrap
and no handshake origination are *one* decision. The proposal: when the backend
is blocked, skip the ICE race and take the existing relay/fail-closed path with a
named reason — which also removes §4.3's storm and the misleading
`traversal_probe_attempts` increments. Real traversal on Linux/macOS then means
the userspace-shared backend, which is where it demonstrably works.

**Rejected, with reasons, in `I4TraversalAttestationPlan_2026-08-05.md` §0.000:**
a synthetic handshake trigger cannot work (WireGuard rate-limits initiation to
one per 5 s per peer, kernel WG has no force-resend and stores one endpoint per
peer, so 72 probes yield at most one initiation).

### 4.5 Closed — do not re-attempt

**Item 6, endpoint attribution.** With this observation surface, attribution and
parallel racing are mutually exclusive. A confirmation round cannot fire:
WireGuard will not rekey for 120 s against a 240 ms race budget, so its causal
path is closed while its coincidental path stays open. What is lost is the
FIS-0009 re-ranking optimisation — a performance feature, not a security control.

## 5. Open decisions — do NOT decide these silently

- **D2 genesis, Windows half.** Windows cannot hold a gossip identity (the daemon
  rejects a configured secret; the transport is unix-only), yet the shipped
  Windows anchor bootstrap genesises a node. It still publishes a keyless value.
  D4 was answered "macOS only", which knowingly accepts this.
- **D3 `--force` re-mint.** Default taken: **keep it**. Dropping it is a measured
  install-breaking regression — the guard is a hard error and the passphrase is
  regenerated every run, so a surviving secret would be sealed under the old
  passphrase and the daemon would refuse to boot. Revisit only with that in hand.
- **Out-of-band snapshot distribution.** `load_membership_snapshot` verifies a
  self-computed digest and **no signature**. If any operator workflow ships
  snapshot files by scp or config management, that channel bypasses the
  pinned-owner gate and raises the severity of the capability-gate finding.
  Unanswerable from the code.
- **D1 fleet migration** was answered "migrate all" and is now much cheaper than
  its own design doc assumed: `verify_attested_snapshot` enforces epoch
  *monotonicity*, not chain reachability, so N rotations apply locally, attest
  once, and distribute once. The ±2 skew-window outage does not bind.
