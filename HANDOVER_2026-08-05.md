## 5. Lessons that cost real time here

**Every one of these was me being confidently wrong from a surface reading.**

- **Grepping a name and inheriting another consumer's mechanics.** Cost two plan
  revisions. `RUSTYNET_ASSIGNMENT_SIGNING_SECRET` is read by two unrelated
  consumers with *mutually exclusive* permission policies; the doc comment that
  seemed to endorse it referred to the other one. Before copying a precedent,
  read the code that *consumes* it, not the code that names it.
- **Enumerating callers by one grep pattern.** "Three callers, all netcheck" — there
  were four, and the fourth used a helper instead of the literal searched for.
  That miscount nearly bricked a live-lab suite.
- **Range notation in a list.** Counting visible tokens in the security ledger gave
  36; expanding `ENR-10…ENR-12` gives 41. **Two readers have now made this
  mistake** — the method is written into the ledger.
- **Tautological tests, twice.** Both asserted properties of literals the test
  itself declared, so the production rule could be deleted and they still passed.
  If a test cannot fail, it is a comment.
- **`git checkout` during mutation testing, three times.** It restores to the last
  *commit*. Uncommitted work in the same file dies with the mutation. **Commit
  first — always.**
- **Grepping test output too narrowly.** `head -3` on `test result:` lines shows
  unrelated targets reporting `0 passed` and reads exactly like a clean run.
