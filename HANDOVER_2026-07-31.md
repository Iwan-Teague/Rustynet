## 0. How you must work — non-negotiable

**Security is not compromisable.** Not "important", not "a priority" — it is the
constraint everything else fits inside. If a change makes something faster,
simpler, or nicer to use at the cost of a security property, the answer is no,
and you say so plainly rather than looking for a middle path. Read
`documents/SecurityMinimumBar.md` and `CLAUDE.md` §3/§4 before touching a
trust-sensitive path. Fail-closed and default-deny are defaults, not options.

**Good user experience is the very next thing after that**, and it genuinely
matters — this is a product people have to run. A control that is correct but
undiagnosable, or that fails closed in a way an operator cannot understand or
recover from, is a bad control. When you have a choice between two equally
secure designs, pick the one an operator can understand at 2am.

**Use adversarial sub-agents. Every time.** Spawn a general-purpose Opus agent to
adversarially review (a) every plan before you implement it, and (b) every
implementation after you write it. Brief them to REFUTE, tell them a review that
endorses is a failed review, and tell them to verify claims against actual code
with file:line citations. This is not ceremony — on 2026-07-30 it caught, in

proposed building something that already shipped; three issuance designs that all

## 3. The lesson that has now cost three designs

> **A signal was trusted because of what it is named, not because of what it proves.**

- The co-location gate keyed on a peer's *self-asserted* reflexive address —
  which the signature proves came from that peer, not that it is true. It
  *rewarded* the attack it targeted.
- The I4 plan treated `TraversalProbeStatus` as proof of reachability. It is not:
  the **fail-closed arm programs the highest-priority candidate anyway** and
  reports `decision: Direct`, and priority is attacker-chosen. Implementing it
  would have programmed a victim's IP.
- An earlier IPv6 fix (`f2e084d9`) introduced a new false-positive of the exact
  class it was written to eliminate.

**The cheap check that catches all three: before relying on a signal, read the
code that WRITES it — especially its failure branch.**

## 4. Traps that cost real time

- **Stop the lab VMs before a full gate.** Same commit, same green result: 128 s
  with VMs stopped, **668 s** with 7 UTM guests up (`syspolicyd` had burned 516
  min of CPU validating binaries; swap exhausted). Documented in CLAUDE.md §7.
- **A slow gate and a hung gate look identical at the parent.** `cargo-nextest`
  sits at 0% CPU in both cases — it is the scheduler. Only the presence of test
  binaries beneath it distinguishes them. Do not extrapolate progress from
  nextest's stdout; it block-buffers off-TTY and interleaves binaries.
- **Never edit the tree while a gate runs.** Two runs were burned this way. Use a
  git worktree, or leave it alone.
- **`git commit -F -` with a heredoc hangs** in this harness. Write the message to
  a file and use `-F <file>`.
- **zsh does not word-split unquoted `$VAR`** — inline multi-flag SSH options.
- **Commits are authored `Iwan-Teague <teague.iwan@outlook.com>` only.** Never add
  a Claude `Co-Authored-By` trailer.
- **`RUSTYNET_SOURCE_COMMIT` reads `unset` on the KVM guests** — it is not a
  reliable way to tell what a guest runs. Deploy explicitly and check binary mtime.
